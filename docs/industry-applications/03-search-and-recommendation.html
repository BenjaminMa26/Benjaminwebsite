1 Search & Recommendation Systems: A Practical Overview

2 Introduction

This guide covers the essential components of search and recommendation systems for Online-to-Offline (O2O) platforms. Instead of full implementations, we focus on architecture, key decisions, and practical patterns.

3 System Architecture Overview

User Query → Query Understanding → Candidate Recall → Ranking → Display
     ↓              ↓                    ↓              ↓
  "sushi"    Intent: food         200 items        Top 10
             Location: nearby   (multi-strategy)   (LTR)

3.1 Three Main Subsystems

  1. Query Understanding - Transform raw input into structured search
  2. Candidate Recall - Find relevant items (200-500 candidates)
  3. Ranking - Order by relevance + business objectives

4 Query Understanding

Goal: "cheap sushi near me" → {cuisine: sushi, price: low, location: user_gps}

4.1 Pipeline Components

# Conceptual pipeline
class QueryPipeline:
    def process(self, raw_query: str, user_context: dict) -> StructuredQuery:
        tokens = self.tokenize(raw_query)
        entities = self.extract_entities(tokens)      # NER model
        intent = self.classify_intent(tokens)         # BERT classifier
        location = self.resolve_location(entities, user_context)

        return StructuredQuery(
            intent=intent,
            entities=entities,
            location=location
        )

4.2 Key Design Decisions

Component Choice Rationale
Tokenization SpaCy Fast, multilingual
NER BERT fine-tuned 95%+ accuracy on custom entities
Intent Rule-based + ML fallback Low latency, interpretable
Location Resolution GPS + GeoHash Real-time, < 10ms

5 Candidate Recall

Goal: Generate 200-500 diverse candidates efficiently

5.1 Multi-Strategy Recall

strategies = {
    'collaborative_filtering': 0.30,  # Users like you
    'geographic': 0.25,               # Nearby merchants
    'content_based': 0.20,            # Similar to history
    'trending': 0.15,                 # Popular now
    'contextual': 0.10                # Time/weather-based
}

candidates = []
for strategy, weight in strategies.items():
    n = int(total_budget * weight)
    candidates.extend(recall_strategy[strategy](n))

5.2 Geographic Indexing

For location-based recall, use KD-Tree or GeoHash:

# KD-Tree for exact radius search
from sklearn.neighbors import KDTree

tree = KDTree(merchant_locations)
indices = tree.query_radius(user_location, r=radius_km)

# GeoHash for approximate, distributed search
geohash = encode_geohash(lat, lon, precision=6)
candidates = geohash_index[geohash]  # O(1) lookup

Performance Comparison:

  • KD-Tree: O(log n), exact results
  • GeoHash: O(1), approximate, horizontally scalable

8 Recommendation Scenarios

8.1 Common Use Cases

  1. Homepage Recommendations - Multi-strategy recall + personalized ranking
  2. Nearby Search - Geographic recall within radius
  3. Related Items - Collaborative filtering on item views
  4. Promotional Campaigns - Time-sensitive, location-aware
  5. Re-engagement - Push notifications based on history

8.2 Implementation Example

# Example: Homepage recommendations
def homepage_recs(user_id, location, limit=10):
    # Multi-strategy recall
    candidates = []
    candidates += cf_recall(user_id, n=50)
    candidates += geo_recall(location, n=50)
    candidates += trending_recall(n=30)

    # Rank with LTR
    features = extract_features(user_id, candidates, location)
    scores = ltr_model.predict(features)

    # Return top-k
    return sort_by_score(candidates, scores)[:limit]

9 Best Practices

9.1 Query Understanding

  • Use NER models (BERT) for entity extraction
  • Combine rule-based + ML for intent classification
  • Cache frequent queries in Redis

9.2 Candidate Recall

  • Use 3-5 different strategies
  • Allocate budget based on strategy performance
  • Index geographically (KD-Tree or GeoHash)

9.3 Ranking

  • Extract 20-40 features across categories
  • Use XGBoost/LightGBM for LTR
  • Retrain daily with fresh data

9.4 Production Deployment

  • Keep latency < 100ms end-to-end
  • A/B test all major changes
  • Monitor CTR, CVR, GMV daily
  • Set up alerting for metric drops
