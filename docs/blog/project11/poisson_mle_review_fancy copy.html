0.1 Why this report matters

This project asks a deceptively simple question: do firms using Blueprinty’s software receive more patents?

The answer requires more than comparing two averages. Patent counts are non-negative integers, Blueprinty customers are not randomly selected, and firm characteristics such as age and region may also explain differences in patent outcomes.

TipReader promise

By the end, the reader should understand three things: why a Poisson model is appropriate for counts, how maximum likelihood estimation chooses the best parameter values, and how to interpret the Blueprinty customer coefficient carefully.

2 Roadmap

Before diving into formulas, here is the path of the analysis. We start with the business question, build the simplest possible count model, then extend it into a regression model that adjusts for firm characteristics.

3 The Business Question

Blueprinty produces software that helps firms prepare blueprints for patent applications. Their marketing team wants to say that customers using the software are more successful in receiving patent awards.

The challenge is that this is not a randomized experiment. A firm may choose Blueprinty because it is already more patent-focused, larger, older, better resourced, or located in a region with more patent activity. Therefore, a raw difference in patent counts may mix together the software effect and pre-existing differences between firms.

NoteQuestion to keep in mind

Can we find evidence that Blueprinty customers receive more patents after holding age and region fixed?

6 Why a Poisson Model Fits Count Data

The outcome is a count. Counts are different from ordinary continuous outcomes:

  • They cannot be negative.
  • They take integer values: 0, 1, 2, …
  • Their variability often grows as the expected count grows.

A Poisson distribution is the natural starting point for this type of outcome:

\[ Y_i \sim \text{Poisson}(\lambda) \]

where \(\lambda > 0\) is both the mean and variance of the distribution.

TipPlain-English interpretation

In the simple Poisson model, \(\lambda\) means: “the expected number of patents for a typical firm.”

7 Maximum Likelihood Estimation for a Simple Poisson Model

For one observation, the Poisson probability mass function is

\[ f(y_i \mid \lambda) = \frac{e^{-\lambda}\lambda^{y_i}}{y_i!}. \]

Assuming observations are independent, the joint likelihood is

\[ L(\lambda; y_1, \ldots, y_n) = \prod_{i=1}^n \frac{e^{-\lambda}\lambda^{y_i}}{y_i!}. \]

Taking logs turns the product into a sum:

\[ \ell(\lambda) = \sum_{i=1}^n \left[-\lambda + y_i\log(\lambda) - \log(y_i!)\right]. \]

Simplifying:

\[ \ell(\lambda) = -n\lambda + \log(\lambda)\sum_{i=1}^n y_i - \sum_{i=1}^n \log(y_i!). \]

To find the MLE, differentiate and set equal to zero:

\[ \frac{\partial \ell}{\partial \lambda} = -n + \frac{1}{\lambda}\sum_{i=1}^n y_i = 0. \]

Solving gives

\[ \hat{\lambda}_{MLE} = \frac{1}{n}\sum_{i=1}^n y_i = \bar{Y}. \]

NoteWhy this feels right

For a Poisson distribution, the mean is \(\lambda\). So the best-fitting value of \(\lambda\) is simply the sample mean of the observed patent counts.

7.1 Coding the log-likelihood

Show the code 
def poisson_loglikelihood(lambda_value, y):
    """Poisson log-likelihood for a single common rate lambda."""
    if lambda_value <= 0:
        return -np.inf
    return np.sum(
        y * np.log(lambda_value)
        - lambda_value
        - special.gammaln(y + 1)
    )

8 Poisson Regression

The simple model assumes every firm has the same expected patent count. That is too restrictive. A Poisson regression lets the expected count vary by firm:

\[ Y_i \sim \text{Poisson}(\lambda_i), \qquad \lambda_i = \exp(X_i'\beta). \]

The exponential link is important because \(X_i'\beta\) can be any real number, but \(\lambda_i\) must always be positive.

TipHow to read the model

A one-unit increase in a predictor changes the expected count multiplicatively by \(e^{\beta_j}\), holding the other variables fixed.

8.1 Model matrix

The design matrix includes:

  1. an intercept,
  2. age,
  3. age squared,
  4. region indicators, leaving one region out as the reference group,
  5. the Blueprinty customer indicator.
Show the code 
X_df = pd.DataFrame({
    "intercept": 1.0,
    "age": df["age"],
    "age_squared": df["age"] ** 2,
})

region_dummies = pd.get_dummies(df["region"], prefix="region", drop_first=True, dtype=float)
X_df = pd.concat([X_df, region_dummies, df[["iscustomer"]].astype(float)], axis=1)
X = X_df.to_numpy(dtype=float)

One region must be omitted because including all region indicators plus an intercept would create perfect collinearity. The omitted region becomes the reference category.

8.2 Log-likelihood for Poisson regression

Since \(\lambda_i = \exp(X_i'\beta)\), the log-likelihood becomes

\[ \ell(\beta) = \sum_{i=1}^n \left[y_i X_i'\beta - \exp(X_i'\beta) - \log(y_i!)\right]. \]

Show the code 
def poisson_regression_loglikelihood(beta, y, X):
    """Poisson regression log-likelihood."""
    eta = X @ beta
    mu = np.exp(eta)
    return np.sum(y * eta - mu - special.gammaln(y + 1))

def negative_loglikelihood(beta, y, X):
    return -poisson_regression_loglikelihood(beta, y, X)

8.3 Manual MLE using numerical optimization

Show the code 
start = np.zeros(X.shape[1])
start[0] = np.log(Y.mean())

manual_fit = optimize.minimize(
    negative_loglikelihood,
    start,
    args=(Y, X),
    method="BFGS"
)

manual_coef = manual_fit.x
manual_se = np.sqrt(np.diag(manual_fit.hess_inv))

9 Interpreting the Results

The customer coefficient is easiest to read after exponentiating it:

TipCustomer coefficient

The analysis suggests that Blueprinty customers are predicted to receive more patents than similar non-customers after adjusting for firm age and region. In the fitted Poisson model, customer status is associated with about 23% more expected patents, or roughly 0.79 additional patents over five years on average.

However, this should be interpreted as observational evidence, not definitive causal proof. Firms choose whether to use Blueprinty, so customers may differ from non-customers in ways we do not observe, such as R&D budget, patent strategy, engineering quality, or legal support.

The age terms suggest a curved relationship between firm age and patenting. The positive coefficient on age and negative coefficient on age squared imply that expected patent counts rise with age at first, but the increase eventually slows down.

Region coefficients compare each listed region to the omitted reference region. These are controls rather than the main focus, but they help reduce confounding from geographic differences.

10 Translating the Model into a Practical Effect

Poisson regression is multiplicative, so a coefficient is not directly an “additional patents” estimate. To express the result in more intuitive units, construct two counterfactual datasets:

  • \(X_0\): everyone is treated as a non-customer.
  • \(X_1\): everyone is treated as a customer.

Then predict patent counts under each scenario and average the difference.

Show the code 
X0_df = X_df.copy()
X1_df = X_df.copy()
X0_df["iscustomer"] = 0
X1_df["iscustomer"] = 1

pred_0 = np.exp(X0_df.to_numpy(dtype=float) @ glm_fit.params)
pred_1 = np.exp(X1_df.to_numpy(dtype=float) @ glm_fit.params)
average_effect = np.mean(pred_1 - pred_0)

counterfactual_table = pd.DataFrame({
    "scenario": ["All firms set to non-customer", "All firms set to customer", "Average difference"],
    "expected_patents": [pred_0.mean(), pred_1.mean(), average_effect]
})
counterfactual_table["expected_patents"] = counterfactual_table["expected_patents"].round(3)
display(counterfactual_table)
scenario expected_patents
0 All firms set to non-customer 3.436
1 All firms set to customer 4.229
2 Average difference 0.793
NoteCareful interpretation

The counterfactual estimate is the model-based average difference associated with customer status, holding each firm’s observed age and region fixed. It is evidence consistent with Blueprinty’s marketing claim, but it is not definitive causal proof because unobserved differences between customers and non-customers may still matter.

11 Final Takeaways

  • Statistical takeaway
  • Business takeaway
  • Causal takeaway

Poisson regression is appropriate because the outcome is a count. Maximum likelihood estimation chooses the parameters that make the observed patent counts most likely under the model.

After adjusting for age and region, the model predicts higher patent counts for Blueprinty customers. This supports the claim that customers are associated with stronger patent outcomes.

The evidence is observational. A stronger causal design would compare firms before and after adoption, use randomized assignment, or find a credible quasi-experimental source of variation.

## Why a Poisson Model Fits Count Data

The outcome is a **count**. Counts are different from ordinary continuous outcomes:

- They cannot be negative.
- They take integer values: 0, 1, 2, ...
- Their variability often grows as the expected count grows.

A Poisson distribution is the natural starting point for this type of outcome:

$$
Y_i \sim \text{Poisson}(\lambda)
$$

where $\lambda > 0$ is both the mean and variance of the distribution.

::: {.callout-tip title="Plain-English interpretation"}
In the simple Poisson model, $\lambda$ means: "the expected number of patents for a typical firm."
:::

## Maximum Likelihood Estimation for a Simple Poisson Model

For one observation, the Poisson probability mass function is

$$
f(y_i \mid \lambda) = \frac{e^{-\lambda}\lambda^{y_i}}{y_i!}.
$$

Assuming observations are independent, the joint likelihood is

$$
L(\lambda; y_1, \ldots, y_n)
= \prod_{i=1}^n \frac{e^{-\lambda}\lambda^{y_i}}{y_i!}.
$$

Taking logs turns the product into a sum:

$$
\ell(\lambda)
= \sum_{i=1}^n \left[-\lambda + y_i\log(\lambda) - \log(y_i!)\right].
$$

Simplifying:

$$
\ell(\lambda)
= -n\lambda + \log(\lambda)\sum_{i=1}^n y_i - \sum_{i=1}^n \log(y_i!).
$$

To find the MLE, differentiate and set equal to zero:

$$
\frac{\partial \ell}{\partial \lambda}
= -n + \frac{1}{\lambda}\sum_{i=1}^n y_i = 0.
$$

Solving gives

$$
\hat{\lambda}_{MLE} = \frac{1}{n}\sum_{i=1}^n y_i = \bar{Y}.
$$

::: {.callout-note title="Why this feels right"}
For a Poisson distribution, the mean is $\lambda$. So the best-fitting value of $\lambda$ is simply the sample mean of the observed patent counts.
:::

### Coding the log-likelihood

```{python}
#| label: simple-loglikelihood

def poisson_loglikelihood(lambda_value, y):
    """Poisson log-likelihood for a single common rate lambda."""
    if lambda_value <= 0:
        return -np.inf
    return np.sum(
        y * np.log(lambda_value)
        - lambda_value
        - special.gammaln(y + 1)
    )
```

### Visualizing the likelihood

```{python}
#| label: likelihood-curve
#| fig-cap: "The maximum of the log-likelihood occurs at the sample mean, which is the MLE for the simple Poisson model."
lambda_grid = np.linspace(0.5, 8, 300)
ll_values = np.array([poisson_loglikelihood(lam, Y) for lam in lambda_grid])
lambda_hat = Y.mean()

fig, ax = plt.subplots(figsize=(8, 4.5))
ax.plot(lambda_grid, ll_values, linewidth=2)
ax.axvline(lambda_hat, linestyle="--", linewidth=2, label=f"MLE = sample mean = {lambda_hat:.3f}")
ax.scatter([lambda_hat], [poisson_loglikelihood(lambda_hat, Y)], s=60)
ax.set_xlabel("lambda")
ax.set_ylabel("Log-likelihood")
ax.set_title("Finding the MLE visually")
ax.legend(frameon=False)
plt.tight_layout()
plt.show()
```

The curve rises until it reaches the value of $\lambda$ that makes the observed data most likely, then falls. Visually, the MLE is the highest point on the curve.

## Poisson Regression

The simple model assumes every firm has the same expected patent count. That is too restrictive. A Poisson regression lets the expected count vary by firm:

$$
Y_i \sim \text{Poisson}(\lambda_i), \qquad \lambda_i = \exp(X_i'\beta).
$$

The exponential link is important because $X_i'\beta$ can be any real number, but $\lambda_i$ must always be positive.

::: {.callout-tip title="How to read the model"}
A one-unit increase in a predictor changes the expected count multiplicatively by $e^{\beta_j}$, holding the other variables fixed.
:::

### Model matrix

The design matrix includes:

1. an intercept,
2. age,
3. age squared,
4. region indicators, leaving one region out as the reference group,
5. the Blueprinty customer indicator.

```{python}
#| label: model-matrix
X_df = pd.DataFrame({
    "intercept": 1.0,
    "age": df["age"],
    "age_squared": df["age"] ** 2,
})

region_dummies = pd.get_dummies(df["region"], prefix="region", drop_first=True, dtype=float)
X_df = pd.concat([X_df, region_dummies, df[["iscustomer"]].astype(float)], axis=1)
X = X_df.to_numpy(dtype=float)
```

One region must be omitted because including all region indicators plus an intercept would create perfect collinearity. The omitted region becomes the reference category.

### Log-likelihood for Poisson regression

Since $\lambda_i = \exp(X_i'\beta)$, the log-likelihood becomes

$$
\ell(\beta)
= \sum_{i=1}^n \left[y_i X_i'\beta - \exp(X_i'\beta) - \log(y_i!)\right].
$$

```{python}
#| label: regression-loglikelihood

def poisson_regression_loglikelihood(beta, y, X):
    """Poisson regression log-likelihood."""
    eta = X @ beta
    mu = np.exp(eta)
    return np.sum(y * eta - mu - special.gammaln(y + 1))

def negative_loglikelihood(beta, y, X):
    return -poisson_regression_loglikelihood(beta, y, X)
```

### Manual MLE using numerical optimization

```{python}
#| label: manual-optimization
start = np.zeros(X.shape[1])
start[0] = np.log(Y.mean())

manual_fit = optimize.minimize(
    negative_loglikelihood,
    start,
    args=(Y, X),
    method="BFGS"
)

manual_coef = manual_fit.x
manual_se = np.sqrt(np.diag(manual_fit.hess_inv))
```

## Translating the Model into a Practical Effect

Poisson regression is multiplicative, so a coefficient is not directly an "additional patents" estimate. To express the result in more intuitive units, construct two counterfactual datasets:

- $X_0$: everyone is treated as a non-customer.
- $X_1$: everyone is treated as a customer.

Then predict patent counts under each scenario and average the difference.

```{python}
#| label: counterfactual-effect
#| output: asis
X0_df = X_df.copy()
X1_df = X_df.copy()
X0_df["iscustomer"] = 0
X1_df["iscustomer"] = 1

pred_0 = np.exp(X0_df.to_numpy(dtype=float) @ glm_fit.params)
pred_1 = np.exp(X1_df.to_numpy(dtype=float) @ glm_fit.params)
average_effect = np.mean(pred_1 - pred_0)

counterfactual_table = pd.DataFrame({
    "scenario": ["All firms set to non-customer", "All firms set to customer", "Average difference"],
    "expected_patents": [pred_0.mean(), pred_1.mean(), average_effect]
})
counterfactual_table["expected_patents"] = counterfactual_table["expected_patents"].round(3)
display(counterfactual_table)
```

::: {.callout-note title="Careful interpretation"}
The counterfactual estimate is the model-based average difference associated with customer status, holding each firm's observed age and region fixed. It is evidence consistent with Blueprinty's marketing claim, but it is not definitive causal proof because unobserved differences between customers and non-customers may still matter.
:::

## Final Takeaways

::: {.panel-tabset}

### Statistical takeaway

Poisson regression is appropriate because the outcome is a count. Maximum likelihood estimation chooses the parameters that make the observed patent counts most likely under the model.

### Business takeaway

After adjusting for age and region, the model predicts higher patent counts for Blueprinty customers. This supports the claim that customers are associated with stronger patent outcomes.

### Causal takeaway

The evidence is observational. A stronger causal design would compare firms before and after adoption, use randomized assignment, or find a credible quasi-experimental source of variation.

:::
